A clear route to a useful first version.

You and I agree a manageable first release; I test the important journeys and leave room to learn from the people actually using it.

  1. Map the workflow and constraints

    Who uses it, what they need to do, what data it handles and which systems it connects to. For an existing app, I review the code and deployment process first.

  2. Agree the scope and quote

    Define the screens, roles, integrations, acceptance criteria and delivery stages. Identify third-party fees, client inputs and the work that can wait.

  3. Build, review and test

    You see working progress and give feedback. Testing covers the critical journeys, permissions, validation and integration failures relevant to your project.

  4. Launch and hand over

    Deploy the agreed release, confirm access and document how it runs. Decide what support and future improvements you want to arrange.

Scope first. Then a useful quote.

A portal with one user role and one integration is a different project from a system with multiple permissions, migrated data and complex rules. I quote around that difference.

Send a short outline: the workflow you want to improve, who will use the app, any existing software, your ideal timing and an approximate budget if you have one.

I’ll explain the likely approach and what needs investigating before a fixed scope can be priced. For a larger build, we can agree separately quoted stages. Hosting and third-party subscriptions are identified separately.

Web application questions

Do I need a custom web application?

Not always. If an existing booking platform, store or form can handle your process well, that may be the sensible choice. Custom development becomes useful when the gaps create repeated work, limit the customer experience or stop systems sharing information.

Can you connect to our existing software?

Often, where it provides a suitable API or supported integration. I check the available access, documentation, data formats and service limits before promising a connection.

Can you add AI features to an application?

Yes, where it earns its place. I hold a Postgraduate Certificate in AI from the University of Auckland and have built retrieval-based (RAG) document-AI prototypes. In an application that could be an assistant that answers from your own documents, or smarter search across your own data. It’s scoped and tested like any other integration, and it’s optional.

How much does a web application cost?

It depends on the workflows, user roles, integrations, existing code and data migration. I prepare a project-specific quote after defining the scope. The website cost guide covers simpler website projects; application work needs its own estimate.

How long will development take?

I set the schedule with you once the first release is defined. External access, content, feedback and integration complexity all affect delivery. Larger products can be broken into stages with a usable first release.

Who owns the code and accounts?

At launch I hand over the agreed custom code and deliverables. Your service accounts should be under your control. Third-party services and open-source components retain their own licences, fees and terms.

Do you work with clients outside Auckland?

Yes. I work remotely with businesses across New Zealand. For Auckland clients, meetings at your business can be arranged by appointment. You deal directly with me throughout the project.
